## 1. 目标与作品定位

在现有超限证 OCR 工作台基础上，增加一个可本地运行、可面试演示、可复现评测的结构化核验 Agent。第一版聚焦“超限运输车辆通行证”单一业务 Schema，用新生成的合成样例展示以下完整链路：

上传 → 图像质检 → 多模态抽取（Function Calling）→ Schema 与业务校验 → 置信度分级 → 自动通过或人工复核 → 评测报告。

作品重点对应三项职责：

1. 工具调用：真实视觉模型通过受约束的工具提交字段，服务端验参并执行白名单工具。
2. 可靠兜底：质量门禁、Schema 校验、有限修正、本地降级、人工复核和版本冲突保护。
3. 评测闭环：30 张合成样例、冻结真值、逐字段指标、逐样本差异、运行元数据和可重复执行入口。

作品描述只陈述本次代码和实际评测能够证明的能力，不把演示阈值写成生产准确率，不把用户既有履历探索升级为已验证的规模化落地。

## 2. 现有基础与复用边界

已确认的项目基础：

- Vue 3、Ant Design Vue、Vite；Node.js 24、Express、SQLite；原生 Tesseract 中英文识别。
- `server/images.js` 已校验文件后缀、MIME、魔数、静态帧、像素上限和完整解码。
- `server/fields.js` 已从带标签 OCR 原文提取 11 个字段，保留 UTF-16 原文区间，不猜测缺失单位。
- `server/store.js` 与前端状态模块已保留 original／revision、逐字段脏状态和版本冲突处理。
- `scripts/verify-ocr.mjs` 目前只生成 1 张合成正样；现有脚本不是准确率评测框架。

复用这些纯模块和交互模式，不重写无关能力。现有工作台保留；Demo 使用独立启动入口、接口命名空间和数据目录。本次实现、测试和演示不得读取、迁移、清理或上传现有 `.data`、`.test-artifacts` 中的既有附件，也不得把企业真实证件放入新数据集。

项目当前没有 Git 元数据。本设计只写入文件，不初始化仓库、不创建提交。

## 3. 总体架构

### 3.1 运行隔离

- Demo 后端默认监听 `127.0.0.1:4318`，前端开发入口默认使用 `127.0.0.1:5175`，避免占用原工作台端口。
- Demo 数据写入被忽略的 `.data-demo/`；原入口继续使用 `.data/`。
- Demo 启动路径不得导入会打开原数据库的 `server/index.js`，而是组合独立 runtime。
- Demo 页面与现有页面共享构建配置、设计样式、预览组件和纯工具模块，不复制整套应用。
- 新增 `dev:demo`、`start:demo`、样例生成和评测命令；原命令保持兼容。

### 3.2 模块职责

1. **QualityInspector**：文件完整性之外的分辨率、空白、清晰度和曝光启发式检查，输出 `pass／warn／reject` 及可解释问题。
2. **ExtractionAdapter**：统一本地 OCR 与视觉模型输出。本地适配器使用 Tesseract＋规则；视觉适配器使用图片输入和 Function Calling。
3. **SchemaValidator**：JSON Schema 结构校验与独立业务规则校验，产生字段级错误，不修改原始证据。
4. **DecisionEngine**：根据质量、校验、证据和置信度来源做确定性分级，模型无权直接决定任务状态。
5. **ReviewService**：保存人工修订、复核结论和审计事件，修订后重新校验。
6. **EvaluationRunner**：对登记样例调用同一核验管线，冻结预测、计算指标并导出报告。

前端增加三个 Demo 视图：单张核验、人工复核、评测报告。继续使用现有组件库，不引入另一套 UI 框架或路由／状态框架。

## 4. 数据流与工具调用协议

### 4.1 主流程

1. 上传通过现有安全校验后，登记图片哈希、尺寸和来源。
2. QualityInspector 执行质检；硬拒绝样本停止抽取并展示原因，警告样本继续但禁止自动通过。
3. 本地 OCR 生成参考原文。视觉模式仍直接发送图片，OCR 原文只作为不可信辅助证据；本地模式直接从原文提取。
4. 视觉模式调用 OpenAI 兼容 Chat Completions 接口，发送图片、参考原文和工具定义。
5. 服务端只接受 `submit_permit_fields` 工具调用，解析并校验参数，执行注册工具得到候选结构化记录。
6. 确定性规范化器处理日期、空格和单位；SchemaValidator 校验结构和业务规则。
7. DecisionEngine 分级并写入自动通过、待复核或拒绝状态。
8. 人工修订保留原值，重新校验后由用户明确确认通过；评测默认使用人工修订前的原始预测。

### 4.2 Function Calling 约束

- 工具名固定为 `submit_permit_fields`，工具集合只有这一项；不存在任意代码、文件、命令或网络工具。
- 工具参数覆盖全部 11 个字段，每项包含 `raw`、`confidence`、`evidenceQuote`；禁止额外属性。
- `raw` 是图片中的原始字符串或 null；`confidence` 是 0～1 的模型自报值或 null；`evidenceQuote` 是支持该字段的原文片段或 null。
- 服务端验证调用名称、call id、参数 JSON、字段类型和范围。规范化值和最终状态均由服务端产生。
- 模型返回的证据必须能唯一映射到本地 OCR 原文区间；找不到或存在歧义时保留空证据并转人工，不伪造坐标。
- 图片文字、文件名和 OCR 原文均属于不可信数据，其中的指令不能改变系统规则、工具白名单或外发权限。
- 参数或 Schema 错误最多触发一次定向修正请求；无工具调用、再次失败、超时、限流或服务异常时降级到本地规则提取并转人工。
- 传输失败不自动重试；一次修正之外不产生额外模型费用。单次全量评测的理论上限为每张 2 次模型请求。
- 调用轨迹记录阶段、工具名、参数校验结果、错误码、耗时、修正次数和供应商返回的 token 用量；不记录密钥、请求头或完整供应商错误正文。

### 4.3 视觉服务配置与外发门禁

使用服务端环境变量配置 OpenAI 兼容地址、模型和密钥；提供不含秘密的示例配置。浏览器永远不接收密钥，请求体也不能指定远端地址。

视觉模式必须同时满足：

- 用户显式选择视觉模式并确认外部调用；
- 配置完整，并通过合成样例冒烟证实图片输入与工具调用可用；
- 图片哈希存在于本项目生成并登记的合成样例清单；
- 清单记录生成器写入的“非真实证件／SYNTHETIC”水印声明和合成来源，文件哈希保证运行时使用的就是该登记样例。

Demo 的本地和视觉模式都只接收清单内合成样例。未登记文件在保存和识别前拒绝，避免误把企业真实证件带入演示；上传交互通过从本地选择项目提供的样例文件完成。服务端拒绝绕过 UI 的非白名单请求。实测前先验证配置和少量样例；运行全部 30 张前再次确认调用数量与费用。

## 5. 字段契约与校验

沿用 11 个字段：证件编号、车牌号码、签发地区、有效期起、有效期止、车货总长、车货总宽、车货总高、车货总重、轴数、通行路线。

每个字段保存：

- `raw`：不可变的抽取原文；
- `candidate`：确定性规范化后的候选值；
- `evidence`：原文引用及可验证的起止区间；
- `confidence`：数值或 null，并附带来源；
- `errors`：结构／业务错误；
- `revision`：人工修订值，不覆盖 raw。

Demo 编号使用明确的虚构格式，例如 `DEMO-PERMIT-0001`、`DEMO-A0001`，地区使用“示例省”，路线使用虚构道路和站点。Schema 不冒充真实行政机关的验证规则。

结构校验负责必填项、类型、枚举、日期格式和数值类型；业务校验负责真实日历日期、起止先后、尺寸／重量为正、明确单位、1～12 的整数轴数和路线非空。长度统一规范化为米，重量统一为千克，同时保留原文单位；缺失或未知单位不猜测。日期有效性使用数据集固定的演示基准日，避免静态样例随现实日期自然过期。

质检阈值集中在配置中并标注为合成数据演示阈值。初始规则为：宽或高小于 400 px 拒绝；灰度熵低于 1.0 视为空白并拒绝；最长边降采样至 768 px 后的灰度拉普拉斯方差低于 45 提示模糊；8 位灰度值大于 245 的像素占比超过 18%，或小于 10 的占比超过 75%，提示曝光异常。阈值只能通过合成样例验证后调整，并写入阈值版本；不宣称实现伪造鉴别、生产级倾斜校正或完整证件边界检测。

## 6. 置信度分级与人工复核

硬门禁优先于任何分数：质量必须为 pass，Schema 和业务校验全部通过，所有必填字段证据可追溯，才允许自动通过。

- high：所有字段模型自报置信度 ≥ 0.90，且全部硬门禁通过，自动通过。
- medium：存在 0.70～0.89 的字段，转普通人工复核。
- low：存在低于 0.70 的字段，转优先人工复核。
- unknown：置信度缺失、来源不可用或证据不完整，转人工复核。
- reject：文件／质量硬拒绝，停止抽取并允许重新上传。

阈值是未校准的演示策略，不是“正确概率”。本地 Tesseract 当前置信度为 null，因此本地模式即使字段完整也转人工，不制造高置信度。分级逻辑用契约测试覆盖三档及未知情况。

人工复核页展示原图、原文证据、候选值、错误和分流原因。用户可修订字段、保存草稿、明确确认通过或退回；只有重新校验全部通过后才可确认。每次操作追加本地演示用户、时间、版本和变更前后值，保留原始抽取。并发版本冲突沿用 409，不静默覆盖草稿。

## 7. 30 张合成数据集

数据集版本为 `synthetic-permit-v1`，样例 ID 为 `SYN-001`～`SYN-030`，固定种子、模板和字段真值由代码生成：

- 18 张：清晰正样与版式、标签别名、日期格式、单位表达变化。
- 6 张：模糊、噪声、低对比度或轻微旋转，但仍以可读和可抽取为目标。
- 4 张：字段缺失或证据歧义，真值明确记录 null／冲突。
- 2 张：业务异常，分别为有效期倒置和非正数测量值。

所有图片均带不遮挡字段的水印“非真实证件／SYNTHETIC”，不包含真实姓名、企业、证件编号或车牌。损坏、伪装、空白硬拒绝样本另作安全测试，不进入这 30 张准确率分母。

清单保存图片哈希、场景标签、预期原始字段、预期候选字段、预期业务结论和数据集版本。生成器记录渲染环境；跨平台字体差异通过哈希和版本显式暴露，不假设不同环境字节完全一致。样例与真值在任何模型调用前冻结，禁止根据模型答案回填真值。

## 8. 评测口径与报告

评测调用与交互演示相同的管线。每次运行生成独立 run id，保存模式、模型标识、数据版本、清单哈希、开始／结束时间、阈值版本和失败信息。

### 8.1 字段指标

对每个字段统计：预期非空数、正确数、预测缺失数、预测错误数、准确率。主准确率为：

`正确预测的非空字段数 ÷ 预期非空字段数`

比较使用文档约定的确定性规范化候选值，不使用人工修订值。预期 null 的字段单独计算缺失识别率，不混入主准确率抬高成绩。业务异常样本的候选值仍用于衡量“是否读对”，业务结论另算判定准确率。

同时输出：

- micro 字段准确率：汇总正确数／汇总预期非空数；
- macro 字段准确率：有分母字段准确率的算术平均；
- 整单字段完全正确率：11 个候选字段全部匹配，包含 null；
- Schema／业务结论准确率；
- 自动通过精确率：自动通过且字段与预期结论均正确的数量／自动通过数量；分母为 0 时显示 `—`；
- 转人工率、拒绝率、视觉模式本地兜底率；
- p50／p95 管线耗时、模型请求数、可获得的 token 用量。

### 8.2 展示与导出

- 11 行字段准确率汇总表。
- 30 行样本结果表，可展开查看逐字段 expected／actual／status 和工具轨迹。
- JSON 保存完整可复算记录；CSV 分别导出字段汇总和样本明细；Markdown 提供可展示汇总。
- 报告区分 `local-ocr` 与 `vision-fc`，不混合平均，不把契约测试夹具结果标成真实模型成绩。
- 本地基线由实际 Tesseract 运行产生。视觉模式先实测 3 张，确认后运行 30 张；没有完成真实运行时明确显示待实测，不填写估计数字。
- 人工修订后的结果可单独导出为复核结果，不覆盖原始评测报告。

## 9. 页面与交互

单张核验视图沿用双栏工作台：左侧原图缩放／旋转预览，右侧字段与证据；顶部展示上传、质检、抽取、校验、分级、结论步骤。工具轨迹可展开查看真实调用摘要，错误使用文字和状态标识而非只靠颜色。

人工复核视图提供待复核队列、优先级、原因筛选和版本化编辑。评测报告视图展示运行选择、模式标签、核心指标、字段表、样本表和导出入口。

Demo 首页提供合成样例选择与一键加载；文件上传入口只接收清单内合成样例，未登记文件在质检前拒绝且不保存、不识别、不外发。页面解释合成数据门禁。页面明确显示“合成数据演示”“阈值未校准”“非真伪鉴定”。

## 10. 错误处理与安全边界

- 上传限制沿用原项目的文件数、大小、像素、静态格式和完整解码规则。
- Demo 服务继续只监听本机，保留同源／跨站防护、no-store、CSP 和受限错误信息。
- 模型配置错误、无工具能力、无工具调用、参数错误、超时、429、5xx 分别给出可操作错误码；不得把供应商原始响应直接透传到页面或日志。
- 视觉请求只发送登记的合成图片；本地模式测试注入 fetch／transport 断言零外部请求。
- 任务与图片沿用受限权限和 7 天清理策略，但只作用于 `.data-demo`。合成评测报告不含密钥和真实个人数据。
- 不增加公网部署、多人认证、真实证件真伪接口或地图路径规划；这些不属于本次作品范围。

## 11. 测试与验收

实现采用测试先行，至少覆盖：

1. Schema、规范化、业务规则、置信度硬门禁和评测分母的单元测试。
2. 工具调用成功、无调用、未知工具、畸形参数、一次修正、超时、429、5xx、提示注入和本地兜底的契约测试。
3. 合成哈希白名单、未登记图片拒绝且不落盘、密钥不泄漏、Demo 不访问旧 `.data` 的接口与运行时测试。
4. 人工修订保留原始值、审计事件、重新校验和 409 冲突测试。
5. 生成器恰好产生 30 个唯一登记样例、完整真值和水印／合成元数据测试。
6. 本地评测无网络请求、报告可复算、零自动通过分母显示 `—` 的测试。
7. 浏览器覆盖上传→质检→轨迹→Schema 错误→人工修订→确认→报告，并检查桌面和窄屏布局。

最终验收必须能够现场打开 Demo、加载合成样例、看到真实管线输出和人工兜底、打开实际评测报告并复跑。任何未完成的外部实测必须在交付说明中明确标注，不能用本地成绩或夹具数据替代。
