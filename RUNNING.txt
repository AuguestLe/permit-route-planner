超限证本地 OCR — 运行说明

本轮范围
Node.js 24 + Express + SQLite + 原生 Tesseract 5 中英文本地识别，以及 Vue 3 校对工作台。
参考 https://github.com/mingle98/nodeOcr 的原生引擎调用方式和 PSM 3 自动版面识别；本项目直接使用 Node spawn 参数数组调用，不经过 shell。
没有接入地图、货车路径规划或原调度系统。合成样本不代表真实超限证验收。
Tesseract 会出现错字、空格和版式识别误差。本轮使用原生 txt 输出，confidence 为 null，页面不显示虚构的置信度；历史任务保留原有数值和引擎记录。
规则提取仅接受可追溯的标签证据；路线末尾可能混入无标签备注，请逐字核对原图。

启动
1. 安装原生 Tesseract 5：macOS 执行 brew install tesseract。其他系统需自行安装并将 tesseract 加入 PATH。
2. 当前机器可双击 start.command；它优先使用项目 .tools 中的便携 Node 24，并检查原生引擎是否可执行。
   标准环境安装 Node 24 和 Tesseract 后，在项目目录执行 npm install，再执行 npm run dev。
3. 工作台：http://127.0.0.1:5174
4. 后端：http://127.0.0.1:4317
5. 生产运行：npm run build，然后 npm start；访问 http://127.0.0.1:4317。
6. 同时只能运行一个使用端口 4317 的服务；不要重复启动。终端 Ctrl+C 可停止。

引擎配置
默认命令为 tesseract；TESSERACT_BIN 可指定原生可执行文件路径，不能填入带参数的 shell 命令。
默认复用 npm 安装的 chi_sim/eng 模型，首次识别解压到 .data/ocr-models/native，之后使用本地缓存。
TESSDATA_PREFIX 可指定已有模型目录的绝对路径，必须同时包含可读的 chi_sim.traineddata 和 eng.traineddata。
指定目录缺失、模型损坏或引擎缺失时明确失败，不自动回退到 JavaScript、英文单模型或云服务。
缺失引擎错误码为 OCR_ENGINE_MISSING；模型错误码为 OCR_MODEL_MISSING。修复配置后重启服务并手动重试。

隐私与运行限制
安装阶段下载公开程序依赖及中文/英文模型。识别时只读取本地模型，不请求外部 OCR 服务。
服务仅监听 127.0.0.1。没有多人认证，不应通过代理或端口转发开放至公网/局域网。
图片及 SQLite 位于非公开 .data 目录；从创建起保留 7 天，运行期间每分钟清理，启动时补清理。
停机期间无法定时清理；再次启动时会清理到期数据。语言模型不含用户证件，可重复使用。
识别并发为 1，等待队列最多 20 张；每张最多执行 120 秒，失败只允许用户手动重试。
图片支持静态 JPG/JPEG/PNG，1～10 张，单张 10 MiB，总计 50 MiB，单张最多 4000 万像素。
上传与识别分开：创建任务后点击“开始识别”。成功图片不重复识别；失败图片单独重试。
保存校对仅保存 OCR 字段修订，并非路线复核。原始文字与来源索引始终保留。

接口概览（同源调用，无原系统登录）
GET    /api/health
GET    /api/tasks
POST   /api/tasks                         multipart：name、重复 files；Idempotency-Key 为 UUID
GET    /api/tasks/:id
GET    /api/tasks/:id/images/:imageId/file
POST   /api/tasks/:id/recognize            JSON：{version}
POST   /api/tasks/:id/images/:imageId/retry JSON：{version}
PATCH  /api/tasks/:id                      JSON：{version,name?,order?,revisions?:[{imageId,fields}]}
DELETE /api/tasks/:id                      JSON：{version}

任务 JSON 直接返回，不包装 data。错误格式为 {error:{code,message}}。
更新版本过旧返回 409。前端只发送修订字段，不覆盖 original。
OCR 原文字段 original.text 不修改；original.fields 每个值包含 value 和 source。
source 为 {imageId,start,end,text}，索引是原始文字的 UTF-16 区间 [start,end)。
字段键：permitNumber、plateNumber、issuingRegion、validFrom、validTo、length、width、height、weight、axleCount、passRoute。
缺失值为 null；尺寸和重量保留原单位文本，不自动换算或补单位。

验证
npm test            单元和接口测试，包含真实本地 OCR、超时取消、损坏图片及版本/删除恢复。
npm run test:ocr     生成明确标注“非真实证件”的合成中文样本，并调用真实 OCR。
npm run test:browser 先启动 npm run dev 并生成合成样本；使用本机 Chrome 验证 1280×720 工作流。
浏览器验证默认使用 macOS Google Chrome；其他环境通过 CHROME_PATH 设置可执行文件。
TEST_BASE_URL 可切换测试至本机生产服务，例如 http://127.0.0.1:4317。
验证截图及合成图片位于 .test-artifacts。尚需授权真实证件样本，不能据此承诺识别准确率。

结构化核验 Agent Demo（合成数据）
独立入口只处理 `demo/samples` 中登记的 30 张合成样例，不读取旧 `.data`、`.test-artifacts` 或任何企业真实证件附件。Demo 后端仅监听 127.0.0.1:4318，数据写入 `.data-demo/`，报告写入 `demo/reports/`。
启动：安装依赖后运行 `npm run dev:demo`，打开 http://127.0.0.1:5175/demo.html；生产演示先 `npm run build:demo`，再 `npm run start:demo`，打开 http://127.0.0.1:4318/demo.html。
样例：`npm run demo:generate` 只生成 `synthetic-permit-v1` 的 30 张带真值、哈希和“非真实证件 / SYNTHETIC”水印的 PNG；已有冻结清单哈希不一致时拒绝覆盖。
核验流程：合成哈希门禁 → 可解释质检 → 本地 OCR 或视觉工具抽取 → JSON Schema 与业务校验 → 硬门禁分级 → 自动通过或人工复核。视觉工具固定为 `submit_permit_fields`，参数错误最多修正一次，失败降级本地并转人工。
本地评测：`npm run demo:evaluate -- --mode local --all`。本次实际本地基线为 30 张，字段 micro 90.8%、整单字段完全正确 73.3%、转人工 96.7%、自动通过精确率因分母为 0 显示「—」；报告见 `demo/reports/1263823d-21b0-4595-9ad9-09e920fbb3e3/`。
视觉评测：复制 `.env.demo.example` 为 `.env.demo`，由用户在本地填写 `DEMO_VISION_BASE_URL`（HTTPS）、`DEMO_VISION_MODEL`、`DEMO_VISION_API_KEY`；密钥只在服务端。先运行 `npm run demo:evaluate -- --mode vision --limit 3 --confirm-external`，检查结果并另行确认费用后，才可运行 `--mode vision --all --confirm-external`。未完成真实调用时报告必须显示待实测，不得用本地或夹具成绩替代。
隐私门禁：普通本地/视觉上传均只接收清单哈希一致的合成样例；未登记文件不保存、不识别、不外发。本地测试断言零外部请求；视觉模式只允许配置目标、显式确认和登记样例。
质检与置信度阈值是合成数据演示策略，未做真实概率校准；“非真伪鉴定”。本地 Tesseract 置信度为 null，不自动通过。
验证：`npm test`；`npm run build:demo`；启动 Demo 后 `npm run test:demo:browser`。浏览器流程使用 SYN-001，只在本机访问，截图写入 `.data-demo/verification/`。
